# 작업 규칙 (항상 적용)
- 사이클은 항상 RED → GREEN → REFACTOR 순서를 따른다.
- 가장 단순한 실패 테스트부터 쓰고, 통과시킬 최소 코드만 구현하고,
  전부 통과한 뒤에만 리팩터링한다.
- 구현 줄에는 충족한 계약 ID(INV-*/E-*)를 주석으로 단다.
- 구조적 변경과 동작적 변경을 한 커밋에 섞지 않는다(구조 먼저).
- 테스트를 수정·삭제·비활성화하거나 assert True/skip 으로 우회하지 않는다.
- 요청하지 않은 기능을 추가하지 않는다. 작업 끝에 `pytest -q` 로 전부 통과를 확인한다.

## Cursor

`sequential-thinking` MCP는 워크스페이스에 연결되어 있지 않음. 대신 순차적 사고로 분석:

1. 목표: 간단 TODO 웹페이지 + 기존 TDD 워크플로 유지
2. 필수: CRUD + 영속 저장 (인증·SPA 제외)
3. 저장: 메모리(1단계) → SQLite(2단계)
4. 프론트: Jinja2 서버 렌더링 최적
5. ECB 매핑: `src/todo.py`, `src/app.py`, `tests/entity/`, `tests/boundary/`
6. **결론:** Flask + Jinja2 + pytest + 메모리/SQLite
