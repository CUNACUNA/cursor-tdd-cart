## 1. 요약

이번 세션에서는 MomTest 방식 Product Discovery 프레임워크를 적용해 **장바구니 할인 계산기** 도메인 규칙을 발견했다.

1차 분석(요구사항 미제공): 프로젝트명·ECB 구조만 확인, **계약 ID 부여 불가** — MomTest 질문 14개와 OOS-001~009 산출.
2차 분석(인터뷰 메모·주문 #1107 제공): 테스트 가능 계약 **5건** 확정, OOS **8건** 유지.

핵심 규칙(근거 있음):
- 소계 = Σ(단가 × 수량) — `INV-001`
- 소계 > 50,000원 → 10% 할인(×0.9) — `AC-001`
- 할인 순서: 문턱 → VIP 고정 — `INV-002`
- VIP 추가 5%(×0.95) — `AC-002`, `AC-003`

검산: 66,000→59,400, 60,000→54,000 (제공 사례와 일치). VIP 수치 사례는 없으나 규칙 문장으로 AC-002 부여.

## 2. 핵심 결정·산출물

### 핵심 결정

| 결정 | 내용 |
|------|------|
| 계약 범위 | Entity(`cart.py`)만 — Boundary `E-*`는 입력 오류 사례 없어 제외 |
| 문턱 조건 | `subtotal > 50000` (「넘으면」→ `>`; `=50000` 사례 없음 → OOS-001) |
| 할인 순서 | 문턱(10%) → VIP(5%) — `INV-002` 불변식 |
| 미확정 항목 | 5만 원 이하·정확히 5만 원·반올림·VIP+저소계 → OOS, Discovery 질문 6개 잔존 |

### 확정 계약 ID

| ID | 계약 요약 | 계층 |
|----|----------|------|
| INV-001 | `subtotal == sum(price_i * qty_i)` | Entity |
| AC-001 | `subtotal > 50000` → `subtotal * 0.9` | Entity |
| INV-002 | 할인 순서: 문턱 → VIP 고정 | Entity |
| AC-002 | VIP 시 문턱 후 `× 0.95` | Entity |
| AC-003 | VIP=False이면 AC-001과 동일 | Entity |

### OOS (구현 금지)

| OOS ID | 제외 동작 |
|--------|----------|
| OOS-001 | `subtotal == 50000` 할인 여부 |
| OOS-002 | `subtotal <= 50000` 원금 반환 |
| OOS-003 | 비정수 반올림 규칙 |
| OOS-004 | VIP + 소계 ≤ 50,000 |
| OOS-005 | VIP만, 문턱 미적용 |
| OOS-006 | `E-*` 입력 오류 계약 |
| OOS-007 | 쿠폰·세금·배송비·포인트 |
| OOS-008 | Flask `app.py` Boundary |
